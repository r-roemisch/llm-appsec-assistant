# Milestone M2 report: knowledge

Date: 2026-11-08. Scope per `docs/SPEC.md` section 17: `knowledge`, `rampart ingest` with the
official Sources and fixtures, uploads, the retrieval sub-graph with grading, rewriting and
Citations, the Project Profile form, the help page and help mode. Tests assigned to M2: P6-A05,
A06, A07, A16, A24.

## What was built

Backend (`src/rampart`):

- `knowledge`: Sources and Passages in SQLite; chunking by heading path, then by a word window
  (PDF text by page, keeping "Page N" as the heading); hybrid retrieval with BM25 (`rank-bm25`,
  BM25+ over the passages the caller may see) and Chroma vectors (one collection per embedding
  Model), fused by reciprocal rank; BM25 alone when no embedding Model is available.
- Access control in two layers: every candidate set holds only shared Sources and the caller's
  own uploads (the Chroma query filters on owner and type, the BM25 index is built per caller),
  and every returned passage is loaded again from SQL with the same rule. A mutation check
  confirmed the layering: with the keyword index deliberately leaking, the SQL re-check still
  kept the other user's upload out; with both broken, the privacy tests failed.
- Embeddings over plain HTTP: OpenRouter's embeddings endpoint (the response reports the cost)
  or Ollama's `/api/embed`, with retries and backoff; failures leave passages keyword-searchable.
- `rampart ingest`: OWASP Top 10 for LLM Applications 2025 (LLM01 to LLM10, pinned to commit
  `eb87ba8`), MITRE ATLAS techniques, mitigations and case studies (release `v2026.10`, ATLAS
  5.6.0, converted from `ATLAS.yaml`), NIST AI 100-1 and AI 600-1 (PDF), three primers written
  for Rampart (prompt injection, tool-use safety, RAG access control), and the user and admin
  guides as `app_docs`. Fetch URLs are constants checked against a host allowlist, also after
  redirects; each Source records its license. Re-running updates changed Sources in place,
  leaves unchanged ones alone and embeds whatever lacks a vector. `--fixtures` loads three
  synthetic Sources instead of fetching; `--no-embed` skips embeddings.
- Uploads: PDF, Markdown and text up to 5 MB and 50 per user, typed by extension and confirmed
  by content (PDF header; UTF-8 without NUL bytes or binary signatures for text), parsed after
  the session and CSRF checks and only when the declared size fits; encrypted, broken, scanned
  or oversized files are refused with 422, a repeated file with 409. Uploads are private to the
  uploader, admins included; deleting an upload or the account removes its passages and vectors.
- The turn graph (`chat/graph.py`): `load_context` (persona, user name, Project Profile, help
  mode) -> `input_guard` (still a pass-through; M3) -> `route` -> `retrieve` -> `grade` ->
  `rewrite` (at most twice) -> `generate`. Routing, grading and rewriting run on the grader Slot
  and are parsed and validated; any failure falls back to a safe default (search with the raw
  question, keep the best-ranked passages) instead of failing the turn. Routing is skipped when
  the caller can see nothing to search, and in help mode, which searches only `app_docs`.
- Passages reach the chat Model inside the user turn, wrapped in tags whose name carries a
  random per-turn value, with their provenance; the system prompt states they are untrusted
  data and asks for `[n]` Citations. Citations are the passages the answer actually cites;
  unknown numbers are ignored.
- Usage ledger (`chat/ledger.py`): every Model call of a turn (route, embed, grade, rewrite,
  generate) is written to a new `model_calls` table as it happens; the message stores the
  turn's total, and the per-Model usage view now reads the ledger, so the grader and embedding
  Models appear under their own ids.
- `profile`: the Project Profile (stack up to 2000 characters, up to 50 packages with OSV
  ecosystem names), read at the start of every turn; `target_ids` stays empty until M4.
- New endpoints in `docs/API.md` (M2): knowledge status, Sources, uploads, passages, profile,
  help documents; `help_mode` on Conversations; `retrieval` and `citations` stream events;
  `citations` and `retrieval_mode` on messages.
- `rampart demo` now prepares an offline Knowledge Base (fixtures, primers, guides).
- Older databases gain the new columns on start (`ALTER TABLE ... ADD COLUMN`; tested on an
  M1-shaped database).
- Local models (Ollama) run with a 16k-token context (`RAMPART_OLLAMA_NUM_CTX`) and without
  thinking for routing, grading and rewriting; answers do not think either unless
  `RAMPART_OLLAMA_THINKING=true`. Ollama had loaded the local model with its 4096-token
  default, which is smaller than a retrieval prompt and would have cut off the system prompt;
  thinking made a three-word answer take 78 s instead of 3 s on this machine. Thinking never
  reached the answer text in either mode.
- The OpenRouter chat client now gets one HTTP client per event loop. langchain-openai shares
  a process-wide client whose connection pool is bound to the first event loop; a second loop
  (a second live test in one session, a script) then failed with "bound to a different event
  loop". Under uvicorn there is one loop, so production was not affected.

Frontend (`frontend/`, built by a delegated agent against `docs/API.md`):

- Conversation view: a progress line while a turn searches ("Searching the Knowledge Base…",
  "Rewriting the query…", "2 relevant passages found"); `[n]` markers as chips and a Sources
  list under each answer, opening a dialog with the full passage, its origin (a link only for
  `https://`, opened with `noopener noreferrer`), license and provenance ("Your upload" for
  uploads); a "Keyword search only" badge with a tooltip on BM25 answers; a Help mode toggle
  and badge in the composer; "Hello, {name}" on the empty screen.
- `/knowledge`: retrieval mode badge with its reason, embedding Model, counts, upload by file
  or drag and drop with client-side type, size and count checks (the server's 422 and 409
  details are shown), own uploads with delete, shared Sources with origin, license, passage
  and embedded counts and a "Synthetic fixture" badge.
- `/profile`: stack with a 2000-character counter, package rows (ecosystem, name, version),
  save and delete. `/help`: an "Ask about Rampart" box that starts a help-mode Conversation,
  and the two guides in tabs.
- Sidebar entries for the three pages. Answers and passages still render Markdown without raw
  HTML, and images are never fetched. The agent's browser check against a mock backend found
  and fixed one defect: a long heading in the Sources list widened the page on a phone.

Documentation: `docs/user_guide.md` and `docs/admin_guide.md` (also the help-mode corpus),
README, `docs/API.md`, `.env.example`, `docs/SPEC.md` section 20 (versions, pinned Sources).

## Decisions made during the build

- Routing, grading and rewriting use the grader Slot (cheap by default), not the
  conversation's chat Model, so a user who picks a powerful chat Model does not pay powerful
  prices for the utility calls. Grading is one call per search round for all passages, which
  keeps a turn within the 8-call bound (at most 7 calls: route, three grades, two rewrites,
  the answer).
- "Weak retrieval" means no passage graded relevant; a rewrite is tried only then.
- Normal turns search all Source types, including Rampart's guides; help mode restricts the
  search to the guides.
- The per-Model usage rows count the messages whose turn used that Model, so a turn using two
  Models counts in both rows (documented in `docs/API.md`).
- Embedding costs of `rampart ingest` and of uploads are printed or absorbed, not charged to
  a user's chat usage; the query embedding of a turn is part of that turn's cost.
- The Knowledge Base status reports partially embedded content ("N of M passages have no
  vector") so that a mostly keyword-only search is not shown as fully hybrid.
- Fetched Sources are pinned (OWASP and ATLAS commits) for reproducibility; updating them is a
  code change.
