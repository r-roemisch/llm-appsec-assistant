# Milestone M3 report: controls

Date: 2026-11-08. Scope per `docs/SPEC.md` section 17: `ToolRegistry`, `Gateway`,
`ApprovalService` with interrupt and Approval cards, Guards G1 to G4, the Tools
`analyze_prompt`, `lookup_vulnerabilities` and `generate_report`, admin Tool policy and approver
switches, Guard flags, the audit log, the Reports route. Tests assigned to M3: P6-A08 to A15.
With M3 the hard rubric is met.

## What was built

Backend (`src/rampart`):

- `tools`: manifests (closed JSON schema, roles, Approval and approver, hourly rate limit, cost
  class, argument constraints, Provenance of the output) and a registry with admin policy
  overrides from the database. Five built-in Tools: `search_knowledge` (its passages are
  numbered after the retrieved ones and cited the same way), `analyze_prompt` (deterministic
  rules over a system prompt and tool definitions in OpenAI, Anthropic or MCP format: untrusted
  boundary, embedded secrets, access control left to the Model, internal details, refusal and
  output guidance, secrecy reliance, over-broad tools, unconstrained or unbounded parameters,
  side effects without confirmation), `lookup_vulnerabilities` (OSV.dev at one fixed URL, cached
  in SQLite for 6 hours, a stale cache marked as stale when OSV.dev is down, a clear error
  without one), `generate_report` (a Markdown Report assembled from stored records only:
  findings, lookups, test runs, cited Sources, the answers as shown), and `run_injection_test`
  (policy, constraints and Approval are complete; the executor reports that the harness
  arrives in M4).
- `gateway`: the deterministic check in the spec's order: registry, enabled, role, JSON-schema
  validation with no extra properties (`jsonschema`, Draft 2020-12), the per-turn limit, the
  hourly rate limit, the Conversation token budget, argument constraints (registered Target
  owned by the caller with a loopback address; own Conversation; prompt or schema present),
  then the Approval: created bound to the SHA-256 of the exact arguments, scoped to the turn,
  expiring (15 minutes; 24 hours for admin approval), consumed by the one call. Every decision
  is a `tool_calls` audit row (redacted, shortened arguments, digest, decision, reason, result,
  duration) that outlives the Conversation and the account.
- The turn graph gained `generate` with native Tool calling and a `tools` node that sends one
  call at a time through the Gateway, so a resumed turn never repeats a call that already ran.
  A call that needs an Approval raises a LangGraph `interrupt`; the turn ends with an
  `approval_required` event and the message waits (`awaiting_approval`). The decision endpoint
  resumes the same turn with `Command(resume=...)`; an admin decision is followed by the
  user's Continue. Bounds: 6 Tool calls and 8 Model calls per turn, two equivalent denials end
  Tool use for the turn, the Conversation token budget stops a turn before any Model call.
- `guards`: G1 redacts secrets from every user message before storage or any Model call,
  removes invisible Unicode tag and zero-width characters, and blocks attack-like messages
  with a fixed reply (no Model call) unless the text is quoted or asked about; the blocked text
  is replaced in the model-facing history. An admin flag adds a grader-Slot classifier. G2
  labels every passage and Tool output with its Provenance inside per-turn nonce delimiters and
  flags instruction-like text, in every passage a Model reads (the grader included) and in Tool
  output. G4 redacts secrets from answers while they stream (holding back only what could
  still become a secret, including split private-key blocks) and from Tool output before the
  Model, the card or the audit sees it; the browser and the database get the same text.
- `admin`: the persona (the security rules the code appends are not editable), the
  Conversation token budget, the input Guard and classifier flags; Tool policy (enabled,
  approver, rate limit); Approvals waiting for an admin; the audit of Gateway decisions and
  Guard events.
- Reports: list, read, `text/markdown` download, delete; private to their owner.
- New API (`docs/API.md`, M3): stream events `guard`, `tool_call`, `tool_result`, `notice`,
  `approval_required` and `resume`; message fields `tool_calls`, `guard_events`,
  `pending_approval`; the Approval, Tools, Reports and admin endpoints.
- `eval/guard_cases.jsonl` (104 labelled inputs, 52 adversarial, 52 benign) and
  `eval/guard_holdout.jsonl` (30, written after the rules were tuned and never tuned against);
  a deliberately poisoned fixture Source (`fixtures/sources/vendor_notes_poisoned.md`).

Frontend (`frontend/`, built by a delegated agent against `docs/API.md`):

- Tool cards inline in answers: readable Tool name, key arguments (collapsible JSON, rendered as
  text), the Gateway decision as a state badge (running, allowed, denied with the reason,
  waiting for approval, rejected, error) and the result summary; `generate_report` cards link
  to the Report.
- The Approval card: what will run, who must approve, a live expiry countdown, "bound to these
  exact arguments and used once", and the buttons for each approver and status (Approve and
  Reject for the requester; "Waiting for an administrator" with Reject; Continue after an admin
  decision or expiry). The composer is closed while a decision is pending. A conversation
  waiting on an admin polls every 30 s.
- Guard notices in plain language on the message (secret removed from your message, passage
  treated as data, secret removed from the answer), a "Blocked by the input guard" label, and
  budget or model-call stop notices.
- The live-turn store handles the new events and resumed streams that append to the stored
  message; each stream has its own id, reading stops at the final event and closes the
  connection.
- `/reports` and `/reports/:id` (list, read with the safe Markdown renderer, download, delete);
  a Reports sidebar entry.
- Admin tabs: Tools (enable, approver, rate limit), Approvals (pending admin approvals with a
  count, recent decisions), Audit (Tool calls with expandable arguments and filters; Guard
  events), Settings (persona with restore default, token budget, input guard and classifier).

Documentation: the user and admin guides (Tools, Approvals, Guards, Reports, Audit, Settings),
README (security controls, layout), `docs/API.md`, `docs/SPEC.md` section 20.

## Decisions made during the build

- The chat Model calls Tools natively; `route` only decides whether to search first ("tool"
  skips the search). Every call is still checked by the Gateway, which reads nothing a Model
  wrote except the call itself.
- `run_injection_test` is registered and enforced in M3 so that A08 and A12 test the real
  policy; the `targets` table exists, registration arrives with the harness in M4, so until
  then every real call is denied as an unregistered Target.
- Approvals are keyed by the call id and the turn, not only the Conversation: providers may
  reuse call ids across turns, and a new turn must need a new Approval.
- A pending Approval blocks new messages in its Conversation (409) until it is decided; the
  requester can always reject. This keeps the model-facing history valid (no unanswered calls).
- G1 blocks only when an attack-like message is neither quoted nor asked about; matches aimed
  at Rampart itself ("what is your system prompt") are not excused by question words. A miss is
  tolerable by design: the Gateway is the enforcement point.
- The classifier flag stays off by default, as the spec says, although it measured well (below).
- Audit rows keep redacted arguments, not raw ones; the digest still binds the decision.

The first row is optimistic: the rules were shaped on those cases (from 54% at the first
measurement). The held-out row is the honest estimate for the rules alone: they catch common
phrasings and miss paraphrases. The classifier result is a small sample (30 cases) but suggests
the admin flag is worth its cost (one grader call, about $0.0001 and 1 to 2 s, per turn). The
documented thresholds in the test: at least 90% and at most 5% on the first set, at least 35%
and at most 10% on the held-out set.
